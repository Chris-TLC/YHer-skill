# 各阶段 Token 成本估算 v1

> 日期：2026-06-23
> 战略：只做三个理科（化学→数学→物理），砍掉文科和其他学科
> 口径：token = 输入+输出总和。一次性"建库"成本 vs 持续"运行"成本分开算。

---

## 战略收缩（Chris 决定）

**只做三个理科：化学、数学、物理。** 顺序：化学先做透 → 做成可复制模板 → 数学 → 物理。

为什么砍掉其他：
- 理科有技巧性、可诊断、有标准答案 → 正是 rubric 引擎的强项
- 文科语言类（语文/英语）无固定技巧 → 不适合 rubric 打法
- 地理/政治/历史/生物 → 选的人少、总结性弱、性价比低

路线：**先把化学整个网页做好 → 给同学测试 → 纠正提炼 → 再补数学物理**。

## 阶段D：AI班主任/总规划系统（阶段三）

**关键认知：班主任主要是"运行时"成本，不是"建库"成本。**

- **搭建**：周规划器/日调度/可重排队列 = 纯代码（复用阶段一的 task_machine），几乎不耗 token（~1M 调试）。
- **运行时**：每个学生每周规划约 20K token（读跨科画像+排任务）。

运行成本示例：
- 1000 活跃学生 × 每周 20K × 4周 = **80M token/月**（这是运行，不是一次性）
- 但走缓存命中后实际很便宜，且这是产品赚钱后的成本

## 一句话总结

- **三科全建起来 + 班主任，一次性约 ¥260 / 69M token**。这不贵。
- **大头是视觉切题（通义）+ 入库（DeepSeek）**，引擎代码不重写。
- **建库一次性，运行持续**：建完三科，产品就能跑，运行成本一次托管才¥0.5。
- 钱主要花在"搜集真题 + 视觉切题 + 入库"这条数据管线上，每科约¥90，可控。
