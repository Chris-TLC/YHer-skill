## 0. 三条核心定调（贯穿全方案，防止跑偏/数据污染）

1. **一化儿语料 = 教学灵魂层**（负责「怎么讲」：通俗、风格、八大招式）；**真题库 = 正确性层**（负责「讲什么对」：标准解/得分点/rubric）。两者相乘，不替代。每道真题挂 `[标准解 + rubric + 一化儿讲法chunk + BV/P视频]`。AI 讲题 = 用一化儿口吻复述标准解 + 引流回视频。

2. **资产分两类，物理隔离防污染**：
   - **保留（干净资产）**：知识图谱(65节点)、题型库(13父19子)、一化儿语料chunks、视频。
   - **推倒（过渡实现）**：`private_tutor.py` 硬编码的6专题诊断题、`stage1_demo.py` 散在界面的业务逻辑、关键词占卜式本地打分。这些被「从KG动态生成 + 客观rubric校验」取代。

3. **终极是 iOS/安卓 App**：引擎层零界面依赖；现在就建 FastAPI 后端层，Streamlit 和将来 App 走同一接口。检索做成本地BGE/云端可切换的 Port。

## Chris 已拍板的决策

- ✅ **现在就建后端 API 层**（FastAPI），Streamlit 也走它。
- ✅ **本地 JSON 存储**（零配置可跑），云端再接 Supabase（Port 抽象）。
- ✅ **化学全部知识点做透**，不保留 → 接全部 65 个 KG 节点；题库覆盖全化学。这是「一个可复制模板」，第2-10科是加数据不加引擎。

## A. 目标架构分层

五层，从下到上。**核心边界：engine 引擎层 + data 数据层绝不 import 任何 UI/Streamlit/网络框架**，只纯数据进、dataclass/dict 出。这是「本地跑→搬云端App后端」的关键。

```
├──────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────┤

```

数据流（学生输入→AI教学输出）：
ui收文本 → api POST → orchestrator取session+task+item → ①teach_engine取标准解锚点(item_bank标准解+exam_pattern骨架+检索一化儿讲法/视频) → ②diagnose_engine用rubric客观校验学生答案 → ③llm_client组prompt(魂+标准解+rubric命中+一化儿讲法+八大招式)→DeepSeek → ④mastery融合(客观为主) → ⑤task_machine决策(闸门+时间盒+恶性循环检测) → store落库 → api返回 → ui渲染讲解+视频+进度。

为云端设的边界：`api层`(今天Streamlit直import引擎，明天App走HTTP，调同一引擎)；`RetrieverPort`(本地LocalBgeRetriever 2GB模型 / 云端CloudVectorRetriever 后端零模型)。

## B. 核心模块设计

### B-1 题库与标准解（最核心新建）

`data/item_bank/{topic}.jsonl` 一行一题：
- `item_id, source, region, year, difficulty(T1-T4)`
- `question_type` ★挂题型(exam_pattern.pattern_id)
- `kg_nodes:[str]` ★挂知识图谱node_id
- `stem, sub_questions[{sub_id,stem,answer,score}]`
- `standard_solution{final_answers, solution_steps[{step,action,result,formula}]}` ★正确性层
- `rubric[{point_id,desc,keywords,score,must_have,kg_node}]` ★评分点(诊断校验命脉)
- `yihuier_chunk_ids:[str]` ★灵魂层指针
- `videos[{bv,p_number,completion_criterion}]` ★变现出口
- `traps:[str]` 出题人陷阱(继承exam_pattern.setter_perspective)

接口 `ItemRepository`：`get_item / find_items(kg_node,question_type,difficulty,region,exclude_ids,limit) / get_rubric / get_standard_solution / link_yihuier_chunks`。

导入管线 `scripts/import_items.py`(离线)：原始题→解析→向量匹配题型→向量匹配KG节点→LLM半自动拆rubric(★须人审)→检索挂一化儿chunk→继承视频→写jsonl。

**Chris 采购清单（每题最少5样）**：①题干(数据/图表文字化,化学式纯文本) ②来源(年/卷/题号) ③标准答案(每小问) ④标准解步骤 ⑤每小问分值。能多给：官方评分细则/得分点(=现成rubric,优先搞带细则的真题)。格式Word/Excel/纯文本皆可。**覆盖全化学**(不只5专题)。

局限：文字表述题rubric不如计算题客观(融合权重自动降客观分量)。

### B-2 诊断引擎（客观校验mastery + L1-L4更细）

`MasteryEstimate{value, objective_component, llm_component, weight_objective, confidence, weak_axes, evidence}`。

客观校验逻辑：
```
objective = rubric命中得分/总分
weight_objective = 0.75(计算题) / 0.45(文字题)
value = weight_objective*objective + (1-weight_objective)*llm_self_score
if 漏掉must_have得分点: value = min(value, 0.6)   # LLM不能单方面说过
```
接口 `DiagnoseEngine`：`check_against_rubric / estimate_mastery / build_progressive_questions(kg_node) / decide_next_level`。

L1-L4 从65个KG节点动态生成(取代硬编码)：
- L1概念 ← KG `judgment_criteria_for_mastery`
- L2入口 ← KG `common_failures[].diagnostic_question`(已带诊断问)
- L3陷阱 ← exam_pattern `setter_perspective.how_to_avoid`
- L4真题 ← item_bank真题rubric(客观判)

升降级：当层客观mastery≥0.7升一层，<0.5留同层换common_failure追问，连续2层卡住进T2。

局限：L1-L3仍部分依赖LLM(但对着KG判据打分,非凭空)；硬客观只在L4。

### B-3 教学引擎（根治讲解太表面）

接口 `TeachEngine`：`build_teaching_context / select_depth / detect_vicious_cycle / build_teach_prompt`。
`TeachingContext{standard_anchor, rubric, solving_skeleton, yihuier_voice, thinking_moves, recommended_video}`。

5机制：
1. **标准讲法锚点**(根治致命问题)：prompt强制注入标准解+rubric，指令「围绕每个solution_step讲，覆盖每个得分点，不跳过must_have」。LLM从自由发挥变成把标准解翻成一化儿语气。
2. **一化儿风格层**：注入yihuier_voice chunk+八大招式，「用一化儿口语/比喻/招式复述标准解，内容忠于标准解」。
3. **分层深讲** `select_depth`：fail_streak≥2强制deep(逐行代入数据,写「这量变了→Q怎么变→与K比→平衡怎么动→转化率怎么变」完整因果链)；confirm只追问。
4. **恶性循环检测** `detect_vicious_cycle`：同kg_node连续2+次mastery<0.5且上轮抛了新题→flag→强制micro_explain/inject_video，禁止再抛新题。
5. **严谨vs形象化分级**：默认严谨应试语言；仅当连续答错/明确说不懂才启用形象比喻，比喻后立刻回严谨表述验证。

局限：野题(不在库)无标准解,退化到solving_steps+检索兜底。T3/T5优先用库内真题(正好满足盲测「主动给真题」)。

### B-4 任务状态机

接口 `TaskMachine`：`gate_check / time_action / decide / reorder_queue`。
改进 vs 现状：
1. 闸门只认客观`MasteryEstimate.value`(不信LLM自报)。
2. 时间盒三态：<budget*0.8 on_track；0.8-1.5且接近闸门 extend_current；≥1.5或总时间将尽 compress_later/wrap_up；闸门没过但时间到→标记unfinished_gap进画像不假装过关。
3. 动态重排`reorder_queue`：T1诊断后按weak_axes重排T2-T5。
4. 恶性循环联动：vicious_flag时override为rewind到micro_explain。
`TaskDecision{from_task,to_task,decision,forced_action,time_action,gate_passed,reason}`。

局限：只专题内重排，跨专题/学科是阶段三事；时间盒基于墙钟,学生中途离开会失真。

### B-5 RAG接入层（真正接进+可切换）

`RetrieverPort`(Protocol)：`retrieve / retrieve_with_diagnosis`。
实现：`LocalBgeRetriever`(包现有retrieve.py,本地2GB) / `CloudVectorRetriever`(云向量,阶段一留接口mock,阶段二实接)。
工厂`make_retriever(mode)`由config.yaml决定。

「真正接进」接线（护城河从浪费变命脉）：
| 资产 | 接进 | 字段 |
|---|---|---|
| KG prerequisites | 诊断前置反查(已有) | trace_prerequisites |
| KG judgment_criteria | **诊断mastery判据**(新) | 注入诊断prompt |
| KG common_failures.diagnostic_question | **L2诊断题动态生成**(新) | 取代硬编码 |
| exam_pattern solving_steps | **教学解题骨架**(新) | solving_skeleton |
| exam_pattern setter_perspective | **L3陷阱+防坑**(新) | traps |
| chunks(语料) | **教学风格层**(新,现仅抽视频) | yihuier_voice |
| thinking_patterns | **八大招式**(新) | thinking_moves |
| recommended_videos | 引流(已有,强化criterion) | videos |

关键：retrieve_with_diagnosis返回值已备齐related_nodes/patterns/thinking/chunks，只是private_tutor没用。

### B-6 学生画像与记忆（两层,为阶段二预留）

`UniversalAbility{reading,procedure,metacognition,calculation,transfer,persistence}` 跨学科共享。
`SubjectAbility{subject, kg_mastery:{node_id:MasteryRecord}, pattern_mastery, weak_nodes, mastered_nodes}` 每科一份。
`MasteryRecord{value, evidence[], last_updated, source:rubric|llm|mixed, confidence}` 带证据带来源。
`StudentModel{user_id, universal, subjects:{chemistry:...}, goals, exam_system, region}`。
接口 `StudentModelStore`：`load / update_from_session / get_weak_nodes`。
存储Port：本地`LocalJsonStore`(零配置) / 云端Supabase(现有init_stage1_tutor.sql够用,ability_scores拆universal/subject两段)。

阶段二复用：加学科=加SubjectAbility+学科KG/题库,通用层引擎层零改动。
局限：跨学科迁移是假设,阶段一只建结构不强行迁移。

## F. 严谨成本模型（DeepSeek,¥/M token）

定价(llm_client实际)：input_miss=3.13, input_hit=0.026(便宜120倍,缓存是命门), output=6.26。
缓存机制：系统魂+session静态(KG/标准解)一次托管内不变→命中。每轮真正miss只有学生新输入+新检索chunk。

单次调用成本：普通问答≈¥0.012;诊断单轮≈¥0.010;执行单轮(注入标准解)≈¥0.018;复盘≈¥0.028。
**一次3小时托管≈¥0.53**(命中正常),最坏全miss≈¥1.85。周规划≈¥0.04。

月度(命中正常)：Free(3托管+20问答)≈¥1.83;Plus¥59(12托管+100问答)≈¥7.56(毛利87%);Pro¥129(30托管+300问答)≈¥19.5(毛利85%)。
单位经济：单次托管API成本≈补习班单次(¥100-300)的0.2-0.5%。最坏成本下Pro仍57%毛利(未扣老师分成)。额度建议:Plus15次/月软上限,Pro40次/月,超出¥2/次。

**Codex估算不严谨之处**：①没区分缓存命中/未命中(全按input_miss,高估3-4倍,最大错误) ②没区分调用类型 ③可能漏算output单独定价(2倍input_miss) ④可能用1M窗口当每轮塞满 ⑤max_tokens是上限非实际。
严谨做法：llm_client.chat返回的usage已有真实input/output/cache_hit_tokens,上线后用真实统计校准。

## 贯穿性诚实局限（必须正视）

- 阶段一无看图题/手写识别(题干图表需文字化,答案需文字输入),拍照OCR是App阶段。
- mastery永远是估计值非真实大脑状态;客观rubric把误差从「LLM瞎猜」降到「得分点命中率」,但「口头说会≠真会」的根本不确定性消不掉,靠misconception_probe持续验证。
- 「比90%教师好」是愿景;工程上阶段一只保证「比表面问答准、不讲错、不抛空题」。
